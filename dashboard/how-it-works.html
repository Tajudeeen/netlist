Design

Three layers of fact,
kept separate.

A processor being sealed and a circuit being safe are different claims. Netlist never collapses them into one "is this safe" boolean — each layer carries its own provenance and its own trust assumption.

01 · Derived

Trust: math + chain

A TapeOut netlist is a byte string of NAND, LATCH and REF records. Because those bytes are on chain, gate count and depth can be computed, not claimed. The decoder walks records in a bounded two-pass parse: validate and count signals, then allocate an exact-size array and compute longest paths.

Cross-check that anyone can repeat: for a non-REF circuit, the decoded gate count must equal the processor's own circuitInfo(id).gateCount. On the live X Layer sample, 6 of 6 non-REF circuits matched exactly, 0 mismatches.

REF records are a pointer to another circuit. A 31-byte REF can expand into an arbitrarily large sub-circuit, so this layer reports depthIsBounded() = false rather than claiming a shallow circuit. The separate npm run verify:refs script walks the closure off-chain and reproduces a real REF circuit's reported count.

circuitInfo(id) → (nIn, nOut, nState, gateCount)
netlist(id)     → 0x00 a:u24 b:u24   NAND
                   0x01 d:u24        LATCH
                   0x02 cpu id nIns nOuts ins…   REF

02 · Declared

Trust: named attester

Publisher and auditor attestations live in separate, versioned tracks. The circuit's current holder declares intended behavior; an allowlisted independent auditor can separately review it. Re-attesting increments a version rather than overwriting history, and every read checks the live netlist hash for staleness.

Scope, stated plainly: Netlist's contracts are not deployed on X Layer (there is no deploy key in this repo), so the explorer shows declared facts as unavailable, never as a passing check. The gate-status page becomes live one paste after deployment.

03 · Network

Trust: live RPC

Processor registration, factory seal, beacon implementation, container derivation and activation are all re-read at call time. Seal is three independent claims, not one boolean: factory sealed, beacon implementation pinned, beacon owned by factory.

On live X Layer at the time of writing, the beacon's owner() reads 0x0, so the TAP-10 §13.8 seal test fails closed — an unsealed processor is reported unsealed, never silently assumed safe.
